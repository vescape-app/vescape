# Board identity, tombstones, integer keys, and Favorite deletion protection

Telemetry and Ride Track always key on Board identity, never BLE `device_id` (two Boards can share a BLE MAC, and re-linking moves the address).

- **Boards are tombstoned, never hard-deleted:** deleting sets `boards.deleted_at` and leaves Ride History and Tune Profiles intact. `getBoards()` filters `deleted_at IS NULL`; `getBoard(id)` **deliberately does not** so history can resolve deleted Boards (action callers must check `deletedAt` and refuse). Ordinary upserts must never clear a tombstone.
- **NEVER use `INSERT OR REPLACE` on `boards`:** `ride_track_points` and `telemetry_chunks` reference local `boards.key` (`INTEGER PRIMARY KEY`, DAO-only; `*_id` = UUID, `*_key` = local int). SQLite `REPLACE` deletes and reinserts, minting a new `key` that orphans every `board_key` row and wipes tombstones. Always match on `id` and update in place. Writing telemetry/tracks for an unknown UUID mints a tombstoned Board row.
- **Favorites protect pinned minutes from deletion:** Favorites pin `[startMs, endMs]` time ranges (never ephemeral derived session IDs). `deleteTelemetryRange`, `clearTelemetryHistory`, and retention pruning MUST subtract bucket-aligned protected ranges (keeping up to 59 s past each edge so surviving minute buckets stay truthful). Removing a Favorite only unpins — it never deletes telemetry.
