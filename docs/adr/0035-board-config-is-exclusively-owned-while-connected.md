# Board Link, Refloat config ownership, and full-blob tune writes

- **No runtime transport discovery or self-healing:** connect reads the probe-confirmed `Board Link` (`bleId + transport`) and never falls back to CAN-ping discovery. Re-linking MUST leave the stored Board Link intact while probing and replace it atomically only on save so cancelling or failing never destroys a working link.
- **`Last Known Board Config Values` is read-only — NEVER a write base:** Board Probe mandates a full Refloat config decode before saving a link, but another tool may have edited the board while disconnected. Only fresh current-session raw config bytes + parsed schema may back a write. Writing MUST patch only known tune fields into that full raw blob and preserve every unknown byte — partial writes or re-encoding from a field map can corrupt motor/hardware settings on a balance vehicle.
- **Exclusive session ownership:** a Board accepts one BLE central at a time, so a connected session reads full config once after link trust and refreshes after its own writes (no defensive re-read before every write). This holds only if every app command that changes board config also updates the fresh write base (raw bytes through the encoder, plus decoded values) or drops it; for example, the lights echo on Refloat ≤ 1.2.1 patches `leds.on` / `leds.headlights_on` into it.
- **Version scoping & Link Integrity:** Tune Profiles store semantic values scoped per Board by Refloat **major.minor** (never auto-created on read) so INFO v2 patch/suffixes do not hide existing profiles. Link Integrity compares full versions when the saved identity has them, while legacy major.minor saved identities deliberately accept richer observations sharing that base version. A mismatch clears last-known config and blocks firmware-dependent commands while keeping read-only telemetry alive.
- **VESC-relative Alert Rules** store a field-and-offset relationship, never a copied threshold number.
