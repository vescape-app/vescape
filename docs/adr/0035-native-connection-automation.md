# Native connection automation starts with presence

Vescape will not create a Board Session merely because the app entered the foreground. Native code runs a five-second Board Presence Scan on every foreground entry. The selected Board may promote into a durable Board Session when global Auto Connect is enabled. Other linked Boards may appear as switch-and-connect hints, but the scan never connects them automatically. Explicit Connect creates a persistent Connect Intent immediately. Android uses the existing core service for scanning, starting it in foreground mode immediately with a determinate five-second progress notification and a Stop search action — there is no regular-service-to-foreground promotion path. Foreground-service work is owned explicitly, so the service and its notification end on timeout or Stop search only when no other owner (GPS, Group Ride, Board Session) remains. iOS covers the foreground-to-lock handoff with a short native background task. iOS keeps the scan native and creates no Live Activity until a Board Session starts.

Connection work follows this precedence: an active or reconnecting Board Session, an explicit Connect Intent, Android Auto Start, Auto Connect, then alternative-board hints. Auto Start remains per Board and may wake, select, and connect its Board when no higher-priority owner exists. Add Board scans and Board Probes take exclusive scanner ownership. Successful linking or re-linking persists the Board Link before it selects the Board and creates a Connect Intent.

Manual Disconnect, End ride, Exit, and Android task removal create a board-scoped Automatic Connection Pause using the configured timeout. Explicit Connect clears it. Mechanical teardown, scan cancellation, probe cancellation, and timeout do not create a pause. This replaces the permanent manual-stop tombstone and the separate Auto Start restart gate. Auto Close remains an explicit limit on boardless connecting and reconnecting work.

Native state carries scan purpose, deadline, presence observations, pause deadline, ownership, and decision reasons to JS for rendering. Native code also writes these transitions to the local Event Log and platform logs, including full Board and BLE ids. A finalized Ride Recording may produce a silent ride-summary notification with a deep link to that ride and its final valid battery estimate.
