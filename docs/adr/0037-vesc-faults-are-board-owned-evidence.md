# VESC faults are Board-owned evidence outside Ride History

VESC firmware faults are durable evidence about a Board, not telemetry history, app-authored Board Warnings, or debug-only Diagnostic Events. Store them in a dedicated fault model: one **VESC Fault Occurrence** per activation, lossless **VESC Fault Register Snapshots** as controller evidence, and a self-contained **VESC Fault Capture** for live incidents. This deliberately rejects embedding fault flags in telemetry frames and minute buckets: Ride Recording can be disabled or pruned, while a fault must remain attributable to its Board and independently dismissible without deleting evidence.

Refloat `ALLDATA` fault mode is the live trigger. Repeated observations of one active code stay one occurrence; a clear or code change closes it, and a direct code change opens another. A live occurrence retains every decoded sample Vescape receives from five seconds before detection through two seconds after clear, at the Board Session's achieved response rate. Overlapping occurrences keep independent captures even when that duplicates samples. Captures contain no GPS and never depend on Ride History; a later read may correlate their timestamps with history if needed.

The trigger also sends the fixed, read-only terminal literal `faults` immediately without pausing response-paced telemetry. `COMM_PRINT` has no explicit completion frame, so received output is retained losslessly and marked complete or incomplete; only complete fault blocks become parsed evidence, an incomplete read never means an empty register, and a later safe audit retries it. The newest previously unseen register entry with the same code may enrich the open live occurrence, but code alone is never a global deduplication key. Ambiguous entries remain separate register-discovered occurrences. Safe audits also run around connection lifecycle and stationary opportunities so a missed live trigger can still be recovered from the controller's bounded in-memory register.

Every link or re-link establishes a new register baseline; Boards that predate the feature establish one on their first later connection. Entries already present are saved as discarded register-only occurrences and remain inspectable, but do not drive the Board health indicator. Linking may show their count as information and never fails solely because the best-effort register read failed. Later new entries are ordinary undismissed occurrences. Register-only occurrences preserve discovery time and controller order without fabricating an occurrence timestamp.

The rider sees faults as a separate section beside Board Warnings in the existing Board warning surface. Undismissed occurrences drive the shared icon; dismissing one changes only its presentation state, and a later activation of the same code starts undismissed. A default-on **VESC Fault Collection** App Setting is an emergency kill switch: off means no triggers, audits, new persistence, or fault indicator, while existing evidence remains readable and dismissible. Fault evidence survives Board removal from active use. The current hard-delete/tombstone mismatch is tracked separately in #428.

Existing telemetry `fault_code`, fault flags, forced fault-frame persistence, and minute-bucket fault counts are removed without migration because the app is still in limited testing. Export, raw BLE capture, GPS duplication, firmware/config snapshots, and additional Refloat setpoints or tilt fields are outside this decision.
