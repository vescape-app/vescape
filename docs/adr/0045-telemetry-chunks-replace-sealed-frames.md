# Sealed telemetry lives in columnar deflate Telemetry Chunks; frames are only the write buffer

`telemetry_chunks` holds one raw-deflate blob per `(board_key, minute_start_ms)`; `telemetry_frames` is only the unsealed write buffer, with no decode cache.

- **Recording NEVER seals:** only the `telemetryStorage` Maintenance Job seals closed minutes (verify-before-delete under `DatabaseReplacementFence`) so rides pay zero compression cost.
- **`changed_mask_1` is authoritative (except keyframes):** a keyframe (`flags & 1`) clears all prior columns and supplies every lane regardless of mask; otherwise a set bit replaces the column even when `NULL` (explicit clear — NEVER coalesce `NULL` as "unchanged"), and a clear bit keeps the previous value. Chunks always encode reconstructed full samples.
- **Cross-platform codec contract is decode equivalence, not identical bytes:** raw deflate (RFC 1951, no zlib header) is deliberate across Android, iOS, and server; decoders ignore trailing bytes after the final deflate block because Apple's `COMPRESSION_ZLIB` does not report them.
- **Delta anchor across sealed minutes:** Android buffer deltas chain across minutes, so after minute N seals, minute N+1's first buffer row deltas against a deleted row. Readers merging chunks + buffer from one snapshot MUST anchor from the latest full state (buffer keyframe or chunk sample) _before_ the requested range without counting the anchor toward query limits.
- **SQLite `NULL` uniqueness & buckets:** SQLite never collides `NULL` in unique indexes, and Room cannot declare a partial unique index without diverging fresh vs migrated schemas — keep one unowned chunk (`board_key IS NULL`) per minute in code inside the seal transaction. Minute buckets aggregate full-rate samples while chunks store ~2 Hz, so sealing NEVER rewrites buckets.
