# Accessory bindings release on contention and compare canonical capability JSON

- **Contested ground-clearance bindings release rather than pick a direction:** v1 has no arbitration between multiple ground-clearance claimants (such as nose and tail sensors), so two active claimants release **Remote Tilt** instead of choosing one — picking a winner would choose a correction direction on the rider's behalf and risk tilting the Board the wrong way.
- **Contested bindings keep the manual pad read-only:** `groundClearanceBound` stays true even while bindings are `CONTESTED`, so a rider whose sensors cancel out does not silently regain manual pad control on a Board configured for sensor tilt.
- **Hand-encoded canonical `capabilities_json`:** the stored **Accessory Capability** baseline is serialized by hand with a fixed key order rather than through `JSONObject` / unordered dictionaries. It is string-compared on reconnect to detect moved firmware limits and travels between platforms in database backups; differing key orders would falsely claim every **Accessory** changed after a restore.
- **No partial calibration rows:** **Sensor Tilt Calibration** is keyed on `(accessory_id, capability_id)` (never the Accessory alone) and written only when complete and valid against the live **Accessory Manifest**; saving a valid calibration is the only operation that rewrites the stored `capabilities_json` baseline.
