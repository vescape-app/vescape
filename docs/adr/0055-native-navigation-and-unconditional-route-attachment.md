# Native Navigation uses synchronous ordering tokens and unconditional route attachment

- **Strictly 1:1 with Direction Point, with explicit failure states:** **Navigation** exists for as long as a **Direction Point** does, including failed results (`FETCH_FAILED` vs `NO_PATH_FOUND`), so JS never infers failure from an empty coordinate list. Setting a new target drops the old path immediately; `recompute` and automatic reroute keep a usable drawn path when a new request fails.
- **Synchronous ordering tokens + serialized re-reading writes:** every intent claims a monotonic token synchronously before async work starts so the rider's last tap always wins (claiming inside a coroutine would order by dispatcher scheduling). Persistence serializes all path and **Navigation Profile** writes on one queue and re-reads current state after acquiring the lock; neither serialization nor re-reading alone prevents stale overwrites.
- **Stored as `polyline6` outside the JS settings projection:** persisted in `app_settings` as `polyline6` (~5.6× smaller than coordinate JSON) and excluded from the settings projection JS mirrors so a ~14 KB path never rides on unrelated settings reads. Cold-start restore is read-only (never fetches) and deletes any stored path whose target disagrees with the stored Direction Point.
- **Unconditional nearest-segment projection:** **Route Progress** always projects point-to-segment (never point-to-vertex) onto the nearest leg so a rider who loops away re-attaches automatically, accepting leg-snapping on figure-eight or out-and-back paths — do NOT add a threshold to paper over it. Aim bearing is absolute degrees clockwise from north (matching the Watch Mirror's north-up rotation by GPS course) with a `2.5 s` travel lookahead, floored for standing riders and capped for fast ones.
- **Automatic reroute discipline:** triggered only by `deviationMeters` (never `remainingMeters`), never overlaps, never replaces a usable path with a failure, and backs off from 30 s to 5 min on repeated failures.
