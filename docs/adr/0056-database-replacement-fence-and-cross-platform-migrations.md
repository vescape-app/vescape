# Database Replacement Fence and cross-platform Room–GRDB migration alignment

- **Generation-ticket fencing for background writers:** `DatabaseReplacementFence` serializes background database writers (**Maintenance Job** chunks, **Ride Weather** observations) against Restore and Clear all. A writer takes a ticket when its work starts; a fence bumps the generation so any write whose ticket predates a restore or clear is dropped rather than polluting the replacement database, and a fence waits for at most one in-flight write.
- **Aligned Room–GRDB migration ledger across backups:** GRDB migration identifiers (`v<N>_…`) are named after Android Room schema versions so both migrators move together. iOS exports stamp SQLite `user_version` so Android Room can open and validate the archive; iOS restores of Android backups pre-seed GRDB's migration ledger from the backup manifest's `schemaVersion` so `migrate` runs only genuinely newer steps instead of replaying `v1` against existing tables.
- **Restored database quarantine in one transaction:** before exposing a restored database, both platforms drop every table outside `SHARED_DATABASE_TABLES` (checking foreign keys at commit so stray tables that reference each other drop in any order) and clear the archive's Telemetry storage job state and legacy marker so its write buffer drains again (ADR-0045).
- **Table rebuild by copy, never `DROP COLUMN`:** destructive schema migrations rebuild tables by copy on both platforms to stay compatible with SQLite builds older than 3.35.
