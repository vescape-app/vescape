# Watch Mirror state is latest-value cold state with explicit clears, the wrist fetches radar itself, and ambient never holds the screen on

- **Never use `transferUserInfo` for cold state:** it queues FIFO and delivers every item, so a settings bag changed five times out of range arrives five times and the wrist animates through the rider's undo history. Cold state needs one latest value that survives restart and reconnect (`updateApplicationContext` / Data Layer items); `sendMessage` drops what is unreachable now, so it carries only frames and commands.
- **A cleared watchOS channel is an explicit payload, never a removed key:** Application Context delivery is latest-value-wins with no delete, so an absent key cannot be told apart from a push that never arrived. The route clears as the version with no points, pushed at startup too, or a reconnecting wrist restores a route the rider cleared in an earlier phone process. Android clears by deleting the item. The lights channel always states itself: a teardown omits both switches with `lightsControllable: false`, so what survives a reconnect is "unknown", never the last echo.
- **The wrist reports its wake level on a heartbeat, and silence means asleep:** capability presence proves only that the Watch Mirror is installed; without the wake report the phone pushed 4 Hz into a stopped activity for the whole service lifetime, the largest avoidable drain on both devices. The wrist re-sends every 15 s; 45 s of silence counts as `ASLEEP` on Android and as ambient cadence (never the rider's) on iOS, where `WCSession` reachability already gates sleeping apps. watchOS reports `.inactive` as ambient, since a wrist still drawing wants fewer frames, not none.
- **Disconnect is measured from the frames that arrive, not assumed:** the push rate is a rider setting, so a fixed window would pin every slower cadence to disconnected. `MirrorState` uses three times the longest of the last 8 arrival gaps, clamped to 750 ms–30 s: the longest, because transports deliver in bursts whose last gap is ~0; gaps past the clamp are outages and are not counted.
- **The wrist fetches RainViewer radar itself:** radar is public imagery, not mirrored phone state, a dozen PNGs per refresh, worthless once stale and shown on one page. `transferFile` cannot cancel once the page is left and delivers late; `sendMessageData` is capped below a frame set and drops when the phone is away, exactly when a watch on Wi-Fi could still fetch. The phone still owns position (frames centre on the pushed forecast location, the watch never touches location services), and radar failures are recorded as the wrist's own, not as a dead phone link.
- **Never set `FLAG_KEEP_SCREEN_ON` on the Wear OS Mirror:** it also suppresses ambient, so rides ran the display at full brightness for hours; that was by far the wrist's largest battery cost.
- **Wrist Lights is a one-switch edit the phone composes, with no dead-man:** the phone builds the pair from its own Board truth (`WatchLightsRelay`), so a wrist holding a slightly stale push cannot revert a switch the phone just flipped. `WatchLightsSwitch` is a selector + value, deliberately not the BLE wire mask, where `0b10` would mean the opposite. A light write is idempotent state, so a lost message needs no undo. The wrist settles only on the echoed state or a timeout revert, never by assuming delivery, and offers switches only while the Watch Mirror is live, since retained cold state would otherwise offer an hour-old truth.
