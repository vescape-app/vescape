# Live readouts are Skia text, and charts are prebuilt data-space paths moved by one matrix

- **NEVER drive a readout through `TextInput` `animatedProps`:** every tick then commits through the shadow tree. On Android the chained `AndroidTextInputState` commits overflowed the GC thread stack, and on iOS a text commit racing the UI-thread prop write could blank the value mid-ride. `MonoText` draws in Skia, so a tick is only a repaint. Put a `MonoText` in a canvas that already exists. Use the standalone `MonoValue` only on plain views, because each canvas is a separate native surface.
- **One scalar bundle per telemetry frame:** `liveTelemetryRuntime` projects the frame into plain `TickScalars` on the JS thread, and one UI-thread worklet assigns every SharedValue. Separate `.value =` writes from JS cost one serialization each (`createSerializable` + GC), and that was the largest live-telemetry cost.
- **Vertices live in data space, in seconds:** x is seconds from the domain start and y is in the metric's units, never pixels. The viewport is one 3×3 affine matrix (`viewportMatrix`) applied to a finished path, so a zoom frame does not depend on the ride's sample count. Seconds rather than milliseconds because Skia stores 32-bit floats: a day-long ride in ms quantises to about 8 ms.
- **Min/max LOD pyramid:** each bucket keeps its first, last, min and max `(t, v)`, so a one-sample current spike keeps its exact value and time at every zoom. Bucket widths are powers of two on an absolute `floor(ts / bucketMs)` grid, so levels nest and a worklet picks the level whose buckets are at most one pixel wide (`pickLevel`). Every level is built from the raw samples, so the extremes never pick up rounding error from the level below. The finest level is skipped, because the raw samples cost the same and are exact.
- **Levels are cut into time tiles:** a frame composes only the tiles it can see. Transforming a whole level copied every point of the ride on each deep-zoom frame, which dropped the chart to about ten frames a second.
- **Paths are built from SVG strings:** `Skia.Path.MakeFromSVGString`, with coordinates rounded to three decimals. A `moveTo`/`lineTo` loop makes one native call per vertex, and at tens of thousands of samples it froze the screen for seconds on each dataset change.
- **The viewport is derived, never stored:** only the rider's zoom is a shared value. Each worklet that projects data resolves its own viewport (`viewportFor`), because a viewport shared between worklets can reach the screen a frame before its paths, so the previous dataset briefly flashes squashed. Zoom survives data updates and resets only when the data key changes.
- **Chart focus is a module singleton:** `scrubHeadMs` and `zoomWindowMs` (`chartFocus.ts`) assume that only one ride is scrubbable at a time. Supporting two at once means replacing these singletons.
