# Native→JS mirrors are gated pushes that foreground pulls repair

- **Native stops emitting while the app is backgrounded:** both platforms emit an event only when `frontendActive && observedEvents.contains(name)` (`shouldEmitToFrontend`). iOS keeps the JS thread alive under the `bluetooth-central` and `location` background modes, and the telemetry stream (`onLiveTick`, `onLiveSeries`) flooding it pegged the thread and tripped the OS CPU watchdog (fatal `cpu_resource` kill). Native keeps polling, recording and alerting; only the JS-facing emit stops. Tracking listeners per event also skips emits that no JS code is listening to.
- **Dropped, never queued:** emits made while the app is hidden are lost, and a whole Board Session can start and end in that time. Every mirror therefore pairs live pushes with a pull on mount and on each `AppState → active`. The pull replaces the whole slice with native truth, which repairs both an item added and an item cleared while the app was away.
- **Pushes beat pulls that are in flight:** each push increments a revision counter, and a pull records the counter when it starts. If a push lands before the async read resolves, the pull's `replaceAll` result is discarded, because the push is newer native truth. A failed pull only sets `error` and keeps the last known mirror; the next foreground or push repairs it. Board Warnings, VESC Faults, Board Config Values and motor config values follow this pattern.
- **Pushes are full slices too:** Board Warning and VESC Fault events carry a Board's complete list and replace it (`replaceBoard`). Native replays a snapshot for each Board on subscribe, so a new listener starts consistent. Replacing whole slices keeps every push and pull idempotent.
- **`onAppDataChanged` bypasses the gate:** these events signal low-rate durable-data writes that JS must not miss. JS reloads the matching store by scope, and each store's `load()` does nothing and skips the re-render when the data has not changed. JS still reloads every scope on foreground, because the emit is fire-and-forget and JS may have been torn down while the foreground service kept writing (#174, a stale `lastBattery` age after a ride). To mirror a new store, give its native writes a scope in `AppDataRepository` and add one reloader.
- **Push-only state is re-emitted on foreground:** native re-sends `onMaintenanceState` and `onRideNotices` from its foreground hook, so the screen never keeps a stale running state.
