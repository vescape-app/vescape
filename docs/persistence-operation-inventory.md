# Native persistence operation inventory

Every durable SQLite operation used by the app is listed here. `covered` scenario names refer to fixtures in
`modules/vescape-core/shared/`; Android runs them through the production Room DAO/persistence seams
and macOS runs the same fixture through production GRDB seams. A composite operation covers its
private leaf statements because the transaction, ordering, and rollback are the observable contract.

All SQLite read/write bridge failures are reported with a sanitized operation name. Full disk,
corruption, I/O, cannot-open, and read-only classifications additionally enter the durable app
storage failure state and stop storage actions. Ordinary query/schema/domain failures reject their
operation without disabling BLE, live gauges, or in-memory Alert evaluation. Startup clears a saved
outage only after a real transactional create/write/drop check succeeds.
